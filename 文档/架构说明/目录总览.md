# 大应用目录总览

当前是“单应用模块 + 按功能分包”的学习骨架。已经实现的界面仍是点击计数器；登录、个人中心、设置、网络和数据库都只是预留结构。

## 先找功能，再找层

以下代码路径以 `app/src/main/java/com/example/learningapp/` 为起点：

| 路径 | 中文含义 | 当前状态 |
| --- | --- | --- |
| feature/home/ui | 首页界面 | MainActivity.kt 已移动到这里 |
| feature/home/domain | 首页业务规则 | 预留，可按需使用 |
| feature/home/data | 首页数据访问 | 预留 |
| feature/auth | 登录注册 | ui、domain、data 三个预留包 |
| feature/profile | 个人中心 | ui、domain、data 三个预留包 |
| feature/settings | 应用设置 | ui、domain、data 三个预留包 |
| core/network | 公共网络能力 | 预留 |
| core/database | 公共数据库能力 | 预留 |
| core/preferences | 轻量偏好存储 | 预留 |
| core/model | 跨功能共享类型 | 预留 |
| core/ui | 公共界面组件 | 预留 |
| core/util | 职责明确的小工具 | 预留 |
| navigation | 页面跳转约定 | 预留 |
| di | 对象创建和组装 | 预留 |

## 源码与资料的区别

| 根目录下的路径 | 用途 | 是否用于构建 |
| --- | --- | --- |
| app/src/main | 公共应用源码、资源、清单 | 所有应用版本 |
| app/src/debug | 调试专用内容 | 调试版 |
| app/src/release | 发布专用内容 | 发布版 |
| app/src/test | 电脑上的单元测试 | 对应测试任务；不进应用 APK |
| app/src/androidTest | 手机或模拟器上的测试 | 对应设备测试任务 |
| 文档 | 架构说明与学习路线 | 不自动参与 |
| 设计资料 | 原型、接口约定 | 不自动参与 |

每个目录都放有《文件夹说明.txt》。已有源码的逐行解释在同目录《逐行代码说明.txt》。说明 TXT 已加入 Android 资源忽略规则，不会作为布局或资源参与编译。

## 为什么保留英文

`src/main/java/res/layout/values` 等是工具约定。代码包使用 `feature.home.ui` 这类英文名，便于 Kotlin、Android 工具和团队协作；人读的说明、架构文档和设计资料使用中文。

## 包与模块不是一回事

目前 `settings.gradle.kts` 只注册 `:app`，因此依然是一个 Gradle 应用模块。`feature`、`core` 是模块内部的包，包边界需要开发者遵守，不会自动阻止跨层调用。

等业务、团队或构建速度确实需要时，可以把某个功能拆成单独的 Gradle 库模块，例如 `:feature:auth`、`:core:network`，届时需要增加模块构建配置和依赖声明。只创建文件夹不会自动变成模块；本次没有预建空模块。

参考：[Android 应用架构](https://developer.android.com/topic/architecture)、[业务规则层](https://developer.android.com/topic/architecture/domain-layer)、[构建版本与源码集](https://developer.android.com/build/build-variants)。
